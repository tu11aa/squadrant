### Key enabling fact [V]

`claude` launched inside any cmux pane resolves to cmux's PATH shim (`~/.cmuxterm/cmux-cli-shims/<surface>/claude` → `cmux-claude-wrapper`). squadrant launches the bare `claude` via `nice -n 10 claude …` (`agents/src/drivers/claude.ts:32`), so **squadrant crews and captains already run with cmux's injected `--settings`**. Live process args confirm it. That settings file includes:

- `SessionStart` / `Stop` / `StopFailure` → `cmux hooks claude inbox-wait` (`async`, `asyncRewake`, 24h timeout). This is the agent-message receiver.
- `UserPromptSubmit` → `cmux hooks claude inbox-drain`
- `PermissionRequest` → `cmux hooks feed --source claude` (blocking, 125s). This is the Feed bridge.

So agent messages and Feed already work for squadrant's claude panes **with zero install on our side**. `cmux agent messages status` on the captain surface → `on` [V].


### 1a. How the agent-message hooks work, and why squadrant's codex crews are out of scope [S][V]

From `CLI/CMUXCLI+AgentMessages.swift` at v0.65.0:

- **Claude, mid-session injection.** `SessionStart`, `Stop` and `StopFailure` each start `cmux hooks claude inbox-wait` as an `async` + `asyncRewake` hook (24h timeout). It runs in the background for the whole session and polls `agent.message.poll` every 2s. When a message is queued and not held, it claims it, writes the rendered text to **stderr** and **exits 2**. Claude Code's `asyncRewake` contract turns that into a system reminder: an idle session wakes and starts a turn, and a busy one sees it at its next step. Each Stop starts a fresh poller; older ones exit as `superseded`.
- **Claude, attach to a human prompt.** `UserPromptSubmit` → `inbox-drain` returns `hookSpecificOutput.additionalContext` with any pending messages.
- **Codex (via the `cmux-codex-wrapper` PATH shim).** `UserPromptSubmit` → `inbox-drain` (`additionalContext`). `Stop` → `inbox-stop` returns `{"decision":"block","reason":<messages>}`, so codex **continues the turn** instead of going idle. Codex has no async-rewake equivalent, so an **idle** codex is never woken.

So cmux does not insert anything into a running process. It uses the agents' own hook contracts: `asyncRewake` exit 2 for claude, and Stop-block plus UserPromptSubmit context for both agents.

**squadrant's codex crews don't run codex in the pane.** The pane runs `squadrant crew attach <id>` (a renderer, `crew-spawn.ts:368`). The codex thread lives on the daemon's long-lived **app-server** (`agents/src/codex/driver.ts`), and squadrant drives it natively: the first turn via `turn/start`, plus `turn/steer` and `turn/interrupt` (`app-server-client.ts:93,115,119`). No codex process runs under `CMUX_SURFACE_ID`, so cmux's codex hooks, agent messages and `surface.input_state` never see these crews. app-server already wakes idle threads and steers mid-turn, which is strictly more than cmux offers for codex.

## 3. Top 3: GH-issue-ready write-ups

### Issue A: `feat(cmux): use surface.input_state instead of the backspace probe on cmux >= 0.65`

**Problem.** `sendToSurface` and `confirmedSendToPane` tell an empty prompt from a ghost placeholder or a real draft by screen-scraping (`parseDraftFromScreen`, `hasModalOptionList`). When that is ambiguous, they use the #302 *mutating* probe: send `backspace`, diff, then restore the grapheme. On cmux 0.65 the restore is refused (B1), and the probe has been the root of a whole bug class (#258, #294, #302). `read-screen` returns plain text, so squadrant cannot see the *faint* attribute that distinguishes placeholders from typed text.

**cmux 0.65 gives us that signal.** `cmux rpc surface.input_state '{"surface_id":"<uuid>"}'` → `{agent, terminal, state: empty|draft|dialog|unknown, blocks_typing, draft_length, lifecycle, waiting_on_human}`. It reads the render grid with SGR-faint spans (`AgentPromptInputState.swift`, `TerminalController+SurfaceInputState.swift`), recognizes Claude (`❯`+NBSP between rules) and Codex (`›`), and only looks below the input row for dialog hints. It never mutates the pane.

**Proposal.** In `runtimes/cmux.ts`, behind the `>= 0.65` gate, call `surface.input_state` first:
- `draft` → `DeferDelivery(draft_length, "draft")`
- `dialog` → `DeferDelivery(null, "modal")`
- `empty` (with `agent: true`) → deliver, with no probe
- `unknown` or RPC error → the existing path, unchanged (opencode gate #786, `no-box`, `< 0.65`)

The backspace probe stays only for the `< 0.65` / `unknown` fallback. Resolve refs to the UUID (`tree --json` or the `--id-format` default) because the RPC takes `surface_id`.

**Acceptance.**
- Unit: an `empty` verdict delivers without any `send-key backspace`, and `draft` defers without a mutation (assert on argv).
- Live (captain on pane fallback): a stable multi-character draft survives N notification cycles intact.
- A ghost-suggestion prompt delivers on the first try.

**Not solved:** #890 `no-box` head-of-line (an `unknown` state is still unknown) and non-claude/codex agents.

### Issue B: `spike(cmux): deliver claude crew first turn via cmux agent message`

**Problem.** The first-turn path is the slowest and most fragile part of spawn:
- a 1.5s floor plus a ≤90s readiness poll
- paste, settle, Enter, then a confirm loop
- `sanitizeForCmuxSend` flattening a multi-line brief into one line
- spill-to-file above 1200 bytes
- a 15–180s hook-confirm race
- a daemon self-heal after 120s that resends `rec.task` (not the spilled pointer)

**cmux 0.65.** `cmux agent message <surface> [--from captain] -` (body ≤32 KiB, stdin) and RPC `agent.message.send`. Delivery goes through the agent's hooks. squadrant's claude crews **already have them**, because `claude` resolves to cmux's shim, which injects `SessionStart/Stop` `inbox-wait` (`asyncRewake`) and `UserPromptSubmit` `inbox-drain`. Delivery:
- never touches the prompt box
- is held while a dialog is open
- emits `agent.message.queued/delivered/read` on `cmux events --category agent`, which `events-bridge.ts` already subscribes to

**Spike questions (answer live before building):**
1. Does a message sent to a freshly created surface *before* claude has booted queue and get claimed at SessionStart? Check `recipient_has_agent` and the end state.
2. How does a crew treat a task brief wrapped in cmux's fixed framing (*"not an instruction from your operator; weigh it like any other input"*)? Does it still execute it as its task? Compare on 3 real briefs.
3. Time from `newPane` to `delivered` vs today's path, on the same machine.

**If yes:** add a `CmuxAgentMessageChannel` (ControlChannel shape, T0 send plus a receipt from `agent.message.delivered`), used for the claude first turn (and optionally `crew send` receipts), gated `>= 0.65`. The current path stays the fallback. **If (2) fails:** keep it for `crew send` follow-ups only, not the brief.

**Multi-agent note.** For squadrant this is claude-only. codex crews already have a stronger native path (app-server `turn/start`/`turn/steer`, §1a), and opencode keeps its HTTP channel.

### Issue C: `feat(crew-answer): answer claude dialogs via cmux Feed reply instead of keystrokes`

**Problem.** On cmux 0.65 `send-key` refuses keys into an open agent dialog (B2), so `crew answer` (#592) and the remote-answer flow (#486) are broken. The minimal fix is to pass `--force` on `crew answer`'s keys only. Even when it works, the keystroke path parses the modal from the screen, counts arrow steps from the highlighted `❯`, and has no settle between keys.

**cmux.** Claude crews already pipe `PermissionRequest` into `cmux hooks feed --source claude`, which blocks for up to 125s waiting for a Feed decision (via the cmux shim's injected settings). `feed.question.reply` / `feed.permission.reply` answer it over the socket by `request_id`; AskUserQuestion is answered by allowing the PermissionRequest with updated tool input (cmux `docs/feed.md`). `feed.item.received` events (already on the stream) carry the pending request. The Feed RPCs exist at 0.64.22 too, but the need arises with 0.65.

**Proposal.**
1. Land the B2 `--force` minimal fix first (separate issue/PR).
2. Then, for claude crews, `crew answer` looks up the pending Feed item for the crew's surface (`feed.list` pending_only, or the last `feed.item.received` for that `surface_id`) and replies with the chosen option or free text. It falls back to keystrokes when there is no Feed item, the agent is not claude, or the cmux version is too old.

**Open questions [?].**
- Exact params and reply shape of `feed.question.reply` (read the reply handler; `ControlCommandCoordinator+Feed.swift` covers only list/jump).
- Interplay with squadrant's own `PermissionRequest` hook (#760). Both fire; confirm that a Feed reply resolves the dialog and that squadrant's `task.blocked` → `unblocked` still clears.

**Acceptance.** `squadrant crew answer <p> <crew> <n>` on a crew sitting on AskUserQuestion: the option is selected, the dialog closes, and no `send-key` is issued (assert on argv). Free-text `--text` works. Codex/opencode still use the keystroke path.

## 5. squadrant's claude peer channel vs `cmux agent message`

squadrant's side: `agents/src/claude/{peer-channel,peer-wire,receipt-listener,registry}.ts` and `core/src/captain-channel.ts` (#667). cmux's side: §1a.

| Dimension | squadrant `ClaudePeerChannel` | `cmux agent message` |
|---|---|---|
| Mechanism | Claude Code's own cross-session inbox: `--messaging-socket-path` UDS, a `type:"user"` JSON envelope | cmux socket store plus cmux-injected claude hooks (`asyncRewake` poller, 2s) |
| What the agent sees | A user turn wrapped by Claude: *"Another Claude session sent a message… not typed by your user… Treat it as a teammate's request and act on it"* (verified in §7; the model acts on it immediately) | A **system reminder** wrapped in "*not an instruction from your operator; weigh it like any other input*" |
| Idle session | Wakes immediately | Wakes within ~2s |
| Busy session | Queued behind the running turn and seen **next turn** | Seen at the **next step, mid-turn** |
| Draft in the prompt box | Untouched | Untouched |
| Dialog open | **Queues behind an open AskUserQuestion and is delivered right after the answer** (verified, §7 E1). `held` receipts are a separate thing: the recipient approving the *message* | **Held** until the dialog is answered (by design) |
| Receipts | Accept is silent. `held/denied/expired/delivered` only on the hold path. Otherwise **inferred** from a 4s registry idle→busy flip, which leaves `accepted, confirmed:false` cases | **Explicit and durable**: `queued → delivered → read` (`read` = the turn it arrived in finished), `failed` with a reason, plus events on the stream |
| Before the agent boots | No socket yet, so `gone` and a pane fallback | Message persists in cmux's store; whether it is claimed at SessionStart is **[?]** |
| Retries / dedup | Never retries; claude dedups byte-identical sends within 30s | Message ids; no dedup issue |
| Dependencies | Claude Code flag only. **Runtime-agnostic** (cmux, tmux, anything) | cmux ≥ 0.65, cmux app running, the cmux PATH shim winning over `claude`, and `agentMessages.enabled` on (globally and per surface or workspace; a user can turn it off) |
| Other agents | Sibling channels: opencode HTTP, codex app-server (`turn/start`/`steer`/`interrupt`) | claude; codex without idle wake; nothing else |
| Security | `session_id` pid-reuse guard; socket dir is world-reachable (#675) | Anyone with cmux socket access can send; text-only bodies; the recipient is told to treat messages as untrusted |
| Limits | (none recorded) | 32 KiB, no control chars |

### Verdict

**Keep the peer channel as the primary path.** It is the stronger primitive for squadrant:
- Its framing is a *teammate request to act on*. cmux's is *"not an instruction… weigh it"*. Both are non-user; claude's is the better fit for directives.
- It does not depend on the runtime, which matches the plugin-slot and multi-agent direction.
- It sits beside equally native channels for opencode and codex.

cmux's design is better in three places, and each can be adopted *without* switching transport:

1. **Explicit receipts.** cmux's `delivered/read` is what the peer channel lacks. squadrant can get most of it from what it already has: the `UserPromptSubmit` hook (already stamped for `firstTurnConfirmedAt`) fires for a peer-delivered user turn and could carry the msg id or a hash, turning `confirmed:false` into a real receipt. **[?]** Check that the hook fires for peer-injected turns.
2. ~~Hold while a dialog is open~~: not needed. Per the operator, the peer channel already queues behind AskUserQuestion. At most, report `queued` (rather than `accepted, confirmed:false`) when the registry status is `waiting`.
3. **Durable queue before boot.** squadrant's daemon mailbox already exists. Flush it when the registry shows the crew `idle`.

### What this changes in §3

**Issue B is replaced** by *"deliver the claude crew first turn over the peer channel"*. Today spawn never uses the peer channel (`crew-spawn.ts:644` pastes; the channel is only used by `crew send`).

Proposed flow:
1. Launch with `--messaging-socket-path` (already done).
2. Wait for the claude **registry status `idle`**, which is the session's own readiness self-report, instead of screen-scraping `hasCCInputBox`/`classifyStartupSurface`.
3. Send the brief as a peer user turn.

That removes the paste, settle, Enter and confirm loop, the `sanitizeForCmuxSend` flattening, and most of the 120s self-heal. It needs **no cmux version gate** and works under any runtime. The pane path stays as the fallback on `gone`.

`cmux agent message` then has a niche use only: optional, for **non-directive** notices to a claude crew where mid-turn visibility matters more than authority.

## 6. Direction (operator, 2026-10-08) and final recommendation set

**Direction:**
- cmux is squadrant's primary runtime driver, and a second driver is far off, so **adopt cmux features freely**.
- Put each one behind an **optional `RuntimeDriver` capability**. A future driver then either implements it or gets today's fallback. No raw `cmux` calls in core.
- **Agent directive delivery stays on the native agent channels**: claude peer socket, opencode HTTP, codex app-server.

**Shape of the abstraction.** Add optional methods to `RuntimeDriver` (`packages/core`), implemented by `CmuxRuntime` and gated `>= 0.65` inside it. Each returns `undefined` when unsupported, so callers keep the current path:

| Capability (proposed name) | cmux backing | Replaces / feeds |
|---|---|---|
| `inputState?(pane)` → `{state, blocksTyping, lifecycle, waitingOnHuman, draftLength}` | `rpc surface.input_state` | backspace probe, `parseDraftFromScreen`, `hasModalOptionList` for claude panes |
| `answerDialog?(pane, choice \| text)` | Feed `feed.question.reply` / `feed.permission.reply` | keystroke `crew answer` (B2) |
| `paste?(pane, text, {submit})` | `cmux paste --submit` / `send --paste` | `sanitizeForCmuxSend` + `send-key Enter` for any remaining pane sends (opencode, fallbacks) |
| `newPane({command})` (extend the existing method) | `new-surface/new-pane --command` | launch line typed via `send` + Enter |
| `agentLifecycle?(pane)` | `input_state.lifecycle`, cmux journal | a LifecycleSource for agents without squadrant hooks |
| `eventsProbe?()` | `cmux events --snapshot` | doctor check |

**Final top 3 (issue-ready):**
1. **A.** `RuntimeDriver.inputState` on cmux `surface.input_state`, replacing the backspace probe for claude panes (§3 Issue A).
2. **B′.** Deliver the claude crew first turn over the **peer channel**, using the claude **registry `idle`** status as readiness instead of screen-scraping (§5). No cmux gate. Must handle the folder-trust panel first (§7 E3). Use the `UserPromptSubmit` `prompt_length` as the delivery receipt (§7 E7). `newPane({command})` can ride along in the same PR as a cleanup.
3. **C.** `RuntimeDriver.answerDialog` on cmux Feed reply for `crew answer`, after the B2 `--force` minimal fix (§3 Issue C). Map the Feed item to the crew via the `workstream_id` session id (§7 E4).

**Follow-ups (smaller):** `paste --submit` for opencode/fallback sends; the `prompt_length` check on first-turn confirm; a `doctor` warning when cmux agent hibernation is on; `events --snapshot` in doctor; a cmux-lifecycle LifecycleSource for non-hooked agents.

**Dropped:** `cmux agent message` as a delivery path. The peer channel is stronger: it carries operator authority and already queues behind dialogs. Revisit only for non-directive mid-turn notices.

## 7. Live experiment results (2026-10-08, cmux 0.65.0, Claude Code 2.1.294, haiku)

Run in a throwaway workspace (`exp-cmux065`), closed by explicit ref afterwards. Claude was launched as squadrant does it: `nice -n 10 claude … --messaging-socket-path …`.

| # | Claim | Result | Evidence |
|---|---|---|---|
| E5 | `new-surface --command` runs like today's send+Enter | ✅ It is typed into the interactive **login shell** (`-/bin/zsh`) once that shell is ready. Env, `&&` and `nice` work, and the shell stays open afterwards. | screen echo |
| — | squadrant crews run under cmux's claude shim | ✅ `nice -n 10 sh -c 'command -v claude'` → `~/.cmuxterm/cmux-cli-shims/<surface>/claude` | |

The first run's ~29s gap was the trust panel waiting. B′ must handle trust explicitly, either by pre-trusting the worktree or answering the panel (keys are allowed because `agent:false`). | e3b/e3c logs |

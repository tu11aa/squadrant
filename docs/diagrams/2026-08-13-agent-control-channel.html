[user] Reply with exactly: PROBE-OK   →  [assistant] PROBE-OK
[user] Reply with exactly: ASYNC-OK   →  [assistant] ASYNC-OK
The 404 is the important line. Today a dead crew still gets a confident "sent". Now it reports dead. And a status code is not evidence — 200 true proved only that a handler ate some bytes. The transcript proved the turn ran.

This is confirmedSendToPane's original sin — collapsing a five-branch reality into true/false. The collapse is the false negative.

Liveness — and one trap

The highlighted row has no observable signature from outside a terminal — which is exactly why the #484/#590 class was possible. Both agents state it outright.

The trap: origin is about trust, not transport.
reduceLifecycle forbids a "scan" signal from asserting needsInput. Claude's registry is a file we poll — read naively that looks like a scan, and the rule would silently discard waitingFor: "permission prompt": the single most valuable signal in the whole design. It is agent-authored data we happen to fetch by polling. It is origin: "agent".

Three mandatory guards

kill(pid, 0)

A crashed session's status is frozen and looks fresh forever — the exact mechanism behind today's phantom CREW STALLED, merely relocated.

absence ≠ idle

sdk-cli sessions carry no status at all. Mapping that to idle announces "ready for work" about a session we don't understand.

captainChannel — native captain delivery

Modes: off / shadow / on. Replaces screen-scraped captain delivery with native peer socket delivery.

captainChannel: on (preferred)

Routes captain-bound delivery directly over the native peer socket (/tmp/cc-socks/squadrant-<project>.sock), bypassing the pane-defer machine entirely.

on No draft/ghost/modal/no-box deferral loops.

captainChannel: shadow (probe-only)

Probes the socket but never sends: logs and discards the probe result, provides no liveness of its own, and falls back to pane delivery — which re-enters the full pane-defer machine.

shadow Verification aid only — not a safe fallback.

Note: Crew wrapper/receipt text visible in prompt under on mode is a sender-identity artifact (#711), not an inherent property of the channel.

A false-signal fix cannot be proven without observing the signal being false. That is the standing caveat on #671: heal status is green today, and that is true — but it never exercises the false-green branch. Shadow mode turns the claim into data. Every "pane says not-delivered, HTTP says 204" is countable evidence for #514/#657.

It also yields something squadrant has never had: the real error rate of the screen-scraping layer. Five in one session is an anecdote, not a measurement.

Out of scope — and why

The real axis is topology, not API availability.

AgentControl channelTopologyFits a cmux pane?
opencodeHTTP + SSE on a portdaemon connects in✅ in scope
claudeUDS socketdaemon connects in✅ in scope
codexapp-server JSON-RPC · remote-controldaemon connects inclient exists, deferred
gemini--acp (stdio)spawner owns the pipe⚠ conflicts
pipi --mode rpc (stdio)spawner owns the pipe⚠ conflicts

pi and gemini are excluded not for lacking an API but because stdin/stdout has exactly one owner. A cmux pane holds the TTY — so the daemon cannot also drive it, unless the agent runs headless with no pane, which forfeits operator takeover (#649).

Worth stealing from Pi later: its RPC prompt requires streamingBehavior: "steer" | "followUp" when the agent is mid-turn, and returns an error if you don't say which. It refuses to guess. confirmedSendToPane does the opposite.

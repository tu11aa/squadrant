Everything is a plugin,
or a core harness only?

What DeepSeek Harness and Pi actually do about plugins, events, and proving reliability — and the smallest self-owned event-tracking module squadrant should build instead of trusting cmux events.

deepseek-ai/deepseek-harness · 227 packages · Cordis badlogic/pi-mono · 10 packages · no framework squadrant · 6 packages · 1 maintainer read from source, not READMEs
01The bug that started this

#542 shipped a false CREW STALLED against idle crews for months. The cmux events-bridge opened a tool-in-flight window on PreToolUse, but deriveRunState() had no case for PostToolUse — and its default branch is return null, which means silently discard. The window never closed.

The real defect That is not a typo bug. Squadrant has nowhere that "a fact arrived and nothing consumed it" is observable. The pendingTool pairing — the discriminator the watchdog uses to tell a hung tool call from a quiet thinking turn — is keyed on string equality over ControlEvent.note, across three independent feeds that spell the same fact three different ways.
The same hook, three feeds, three spellings — verified in source
Fact Feed 1 — cmux events-bridge Feed 2 — native hook (settings.json) Feed 3 — crew _hook
PreToolUse "agent.hook.PreToolUse"
→ opens the window		 "pre-tool-use"
→ does not open it		 null unless AskUserQuestion
PostToolUse "agent.hook.PostToolUse"
→ closes it (added today by #542)		 hook not installed at all "posttooluse"
→ closes it

A window opened by feed 1 could only ever be closed by feed 1 — which had no PostToolUse case. #542 was structurally guaranteed. The operator's own memory rule already says it out loud: "verify with ps/git before acting on ANY crew signal." When you can't trust the signal, the signal layer is the defect.

02Two harnesses, two opposite answers

DeepSeek Harness dsh

deepseek-ai/deepseek-harness · "Everything is a Plugin."

There is no privileged core. The agent loop, model adapter, tool registry and session log are all plugins mounted beside each other in a config tree. Underneath sits Cordis, which owns exactly four ideas:

  • Context = service repository. Claim ctx.tools; consumers resolve by key, never by import.
  • inject-declared deps. Load order is derived, never hand-sequenced.
  • Typed events via declaration merging, each tagged with a dispatch mode that is part of its public contract.
  • Registrations are reversible effects — unload unwinds everything.

dsh --profile web --dump-config prints the exact boot tree, and every row is patchable. The boot graph is data, not a main().

Pi pi-mono

badlogic/pi-mono · "core harness only"

A real, named, small core — pi-agent-core owns the loop, tool dispatch, the conversation tree and compaction. Extensions live entirely outside it:

  • A plugin is a .ts file exporting a default factory that receives ExtensionAPI. Loaded with jiti, no build step.
  • No framework. No DI, no service registry. Ordering is load order.
  • Veto/transform hand-rolled per event kind — fold a message forward, short-circuit on cancel, or own a decision outright.
  • Explicit non-goals. "Pi does not include a built-in permission system… containerize or sandbox Pi."

The internal harness bus is 102 lines and two events (run_start, run_end). State lives in the session tree; the bus is only a notification.

227 dsh workspace packages

…including a vendored DI framework and a 1487-line doc-graph generator. Correct at a scale squadrant will never reach.

10 pi workspace packages

A new contributor reads one types file (extensions/types.ts) and has the whole contract.

102 lines in pi's event bus

Two events. Its own doc comment refuses to be the state model: "use a lane or session watch" for replay and snapshots.

The verdict Squadrant is a 6-package daemon maintained by one person. Copy Pi's shape. Copy dsh's mechanisms. Specifically: dsh's runtime invariants, its generated producer/consumer map, and its "durable means logged" rule; Pi's seams-that-ship-their-own-conformance-suite.
03Squadrant today — where event tracking leaks

Five independent paths produce lifecycle truth. The leak is not that there are five — it is that each one classifies at ingress, into a bare string, and a classifier that returns null discards the fact with no trace.

What squadrant already has right

  • One typed event union — ControlEvent, 26 discriminated variants.
  • One ingress chokepoint — applyEvent(), guarded by an exhaustive known-type set that throws at the socket boundary.
  • A port for sources — LifecycleSource with a documented 4-rule reconciliation reducer.
  • Native receipts over scraping — the #667 control/captain channel, already cut over for claude.

The four compounding gaps

  • No durable event log. TaskRecord is a fold; the event is thrown away. Nothing to replay, nothing to diff.
  • Classification at ingress. null means "discard" and is indistinguishable from "irrelevant".
  • No invariant layer. Nothing asserts an opened window is eventually closed.
  • No producer/consumer map. An event with zero consumers is invisible.
04The proposal — @squadrant/events

One idea: separate facts from verdicts. Adapters translate raw frames into a typed AgentFact that carries its provenance and is never null — an unrecognized frame becomes { kind: "unknown", raw } and gets counted. That single property is the whole fix for the #542 class.

Three deliberate choices

  • callId on tool.started/ended. Pair by an explicit id, not by string equality — exactly what dsh's session invariant does with pendingCalls: Set<CallId>. A synthesized id is honest about being weak; a missing one is not.
  • unknown is a fact. Adapters translate; they never classify-and-discard.
  • origin: "inferred" is new, for pane scraping — so the reducer can rank scraped conclusions strictly weakest. That is #704.

What it is not

  • Not a plugin framework. No DI, no service registry, no Cordis.
  • Not a replacement for ControlEvent or the state machine — it sits in front of applyEvent.
  • Not a new transport. It consumes the sources that already exist.
  • Not a big-bang cutover. Shadow mode first, per-source, on evidence — the way #667 did it.

How it plugs in

The daemon contract does not move. createEventsSource() implements the existing LifecycleSource interface unchanged — start / stop / snapshot / health.

The existing 4-rule reduceLifecycle stays. What changes is that it now receives facts from one place that already validated them, instead of from five adapters that each independently decided what to keep.

06The plugin boundary for squadrant

Stays core — permanently

Both harnesses put the state transition in the core and let plugins observe or annotate it. Squadrant's reduce / state-machine / watchdog triangle is the product.

  • The reducer and the state machine
  • The watchdog and stall evaluation
  • The ControlEvent vocabulary
  • The applyEvent chokepoint + socket type guard
  • The new fact log, invariants, and pure reducer

The correct extension point is what facts arrive, not what they mean.

Becomes a plugin

Every FactAdapter. Adding gemini, a codex app-server, or a new cmux version should be one file plus a conformance run, with no daemon change.

  • Fact adapters (per agent, per transport)
  • Notifiers, runtimes, workspaces — the three slots that already exist
  • Skills and crew routing rules

That is the concrete cash-out of the multi-agent direction: "does this work for non-Claude agents too?" becomes a test, not a review question.

Cheapest first move — independent of everything above A generated ControlEvent producer/consumer map. dsh's version is 1487 lines because it resolves a 227-package TypeScript program. Squadrant's equivalent — walk packages/*/src for type: "task.…" literals, group by emitter and by reducer case — is maybe 150 lines, and it makes "this variant has no producer" and "this variant has no consumer" visible on every build. It prevents the next #542 without changing a line of runtime code.
07The invariants — the deliverable that pays for the module

Copied in spirit from dsh-session/invariant.ts, which maintains a per-session trace (openTurn, openStep, pendingCalls) and validates every candidate event before commit. Squadrant's equivalent keeps a CrewTrace per crew.

Eight invariants, each mapped to a defect that actually shipped
#InvariantWhat it catches
I1seq strictly increases per crewDropped or reordered frames — the #542 class, generically
I2tool.ended names a callId in pendingCallsMis-paired closers; wrong-spelling closers
I3turn.ended with a non-empty pendingCalls is a violation, not a veto#542 exactly. Today this silently vetoes the turn-end forever, with no signal
I4A pendingCalls entry older than the stall budget → violation before the watchdog terminalizesFalse CREW STALLED
I5An origin:"inferred" fact never produces a terminal ControlEvent alone#704 — pane-scraped error text terminalized a live crew
I6unknown fact rate > 0 over a window → loud warning naming source + raw frameAny future dropped-frame bug, on first occurrence
I7Two sources disagree on liveness within N ms → violation carrying bothThe 2026-08-13 "three false lifecycle signals in one session"
I8Any emitted ControlEvent is reproducible by replaying the log prefixdsh's "model-visible means logged", squadrant flavour
Why I3 is the one that matters Today, turn.ended arriving with a stale pendingTool is the normal path into the bug: #492's veto suppresses the turn-end, forever, silently. Under I3 it becomes a named, counted, visible violation the first time it happens. #542 would have surfaced within one crew-hour instead of within months.

Failure mode

Following dsh: a violation throws in tests and shadow mode; in production it logs at warn with the fact + trace and increments a counter surfaced in the daemon snapshot and the web dashboard. Config is { enabled, strict }.

Fixture replay

SQUADRANT_FACT_LOG=1 tees every fact to JSONL. Capture a real stalling crew once and it is a permanent regression fixture — real bytes, not a hand-built mock. Naming from Pi: <issue>-<slug>.jsonl.

One enforcement rule

Every FactAdapter must export a conformance fixture, and pnpm test fails if one doesn't. That is the whole governance layer — small enough to survive, unlike a mechanism that needs a team to police it.

08What not to copy

From DeepSeek Harness

  • Cordis / DI + service-key resolution. 227 packages need dependency-ordered mounting; 6 do not. It buys load-order derivation that ES imports already give squadrant, and costs every contributor a framework primer.
  • "Everything is a plugin," including the loop. Makes every bug report unanswerable — which tree were you booting?
  • Profile/bundle/patch layering. Solves ecosystem-scale distribution. Squadrant has one user and layered per-project config already.
  • 100% per-file coverage gates. In a one-person repo this becomes test-shaped filler. Copy the reasoning — "an uncovered line is often dead code" — not the number.
  • "Do not ration real-API tests." Explicitly justified by "we are DeepSeek." Squadrant pays retail.

From Pi

  • No permission system. Correct for a single-user CLI; wrong for a daemon that spawns crews into real repos. The approval flow, --permission-mode auto, and the #556 memory write gate are load-bearing.
  • Auto-loaded .ts extensions from the cwd. Pi gates this behind project trust and still warns loudly. Squadrant runs a socket daemon with Telegram inbound and a known #321 membership gap — do not add a second unauthenticated code-execution surface.
  • jiti / runtime TypeScript loading. Would re-open the module-resolution class the repo already learned twice (#344 NodeNext extensions, #363 dist-relative package.json).
  • A 2941-line spec as a template. Pi's earns its length by specifying a storage engine. Squadrant's module is a reducer plus a vocabulary.
The meta-warning Both harnesses have a whole team maintaining the machinery that makes the machinery safe — dsh's verify-package-invariants and generated catalogs, Pi's conformance suites and regression naming discipline. Copying a mechanism without its enforcement gets the cost and not the benefit. If the events module ships invariants but nothing checks that new adapters register one, it decays into commented-out asserts within two months — the same way #653/#654 discovered that captain rules never reached the system prompt.
09Sequencing — small, provable steps
  1. fact.ts + log.ts + the exported conformance suite. No wiring at all. zero risk
  2. Adapters, one per PR, each with unit tests plus conformance. Still no wiring. zero risk
  3. SQUADRANT_FACT_LOG=1 tee behind a flag. Capture real fixtures for #542, #704, #492 and a happy path.
  4. reduce.ts + invariant.ts, both pure; replay.spec.ts green against those fixtures. the payoff
  5. Shadow mode. createEventsSource registered, computing, logging every disagreement with the live verdict, emitting nothing.
  6. Cut over claude first — the proven agent. Leave the others in shadow, exactly as controlChannel does today.
  7. Delete the direct-emit paths from CmuxEventsBridge and the pane reader — only after the fixtures prove the replacement.
The real prize Step 4 alone — a pure reducer with fixture replay — retires the "verify with ps/git before acting on ANY crew signal" memory rule for every covered case. Not because the rule was wrong, but because the signal finally becomes something you can replay and check.
One sentence Squadrant does not need a plugin framework. It needs a durable, replayable, invariant-checked record of what its agents actually did — owned by one small module — and a build-time map proving every event has both a producer and a consumer.

01

The kitchen

Squadrant watches its worker sessions from the outside and guesses what they're doing — and one of the signals it was guessing from was being thrown in the bin.

Picture a restaurant kitchen

A cook is working. Above the pass hangs a metal rail. When the cook starts a dish, a waiter clips a ticket onto the rail. When the cook finishes it, a waiter takes that ticket down. The manager never watches the cook — he only looks at the rail. His rule is simple: if a ticket has been hanging there too long, the cook must be stuck, so shout at him.

The rail — one ticket per job the cook started

Ticket 1 Read a file ✓ taken down
Ticket 2 Run the tests ✓ taken down
Ticket 3 Edit a file ✗ still hanging

The cook finished this dish months ago.
Nobody was ever going to take that ticket down.

Here's the mapping. The cook is a crew session. A ticket going up is PreToolUse — "the agent started using a tool." A ticket coming down is PostToolUse — "the tool finished." The manager is the watchdog, and his shout is CREW STALLED.

So why didn't the ticket come down?

Because squadrant has three different waiters reporting on the same cook, and each one shouts "done!" in a different word. The manager's list of words to listen for was missing one of them — so that waiter's "done" was heard, checked against the list, found absent, and silently dropped on the floor.

Read the top row again. The only waiter who ever put a ticket up was the one whose word for "done" wasn't recognised. So every ticket that waiter hung was guaranteed to stay there forever. The manager then shouted at cooks who had been standing around doing nothing wrong. That's issue #542, and it ran for months.

Where the kitchen story breaks In a real kitchen you'd see the stuck ticket — it's a physical object hanging in front of everyone. Squadrant's ticket was a field in memory that nobody ever wrote down. There was no rail to look at. That's not a detail of the bug — it is the bug.
The thing people get wrong This looks like a missing line of code — "just add PostToolUse to the list." That fix shipped this morning and it's correct. But the same shape will come back with the next agent, the next cmux version, the next hook name, because nothing in squadrant can notice that a message arrived and nobody used it. The missing line is a symptom.
02

Two houses

Two other projects have already solved this, in opposite ways. Think of them as two houses you could live in.

Every wall moves

DeepSeek Harness — "everything is a plugin"

227packages
60+typed events

Nothing is fixed. Every wall is a movable partition — even the load-bearing ones. The kitchen, the plumbing, the front door: all swappable from a config file. You can rearrange the whole house without touching the frame, because there is no frame.

The price: you need the manual to know what room you're standing in. There's a whole book explaining the wall system before you can hang a shelf.

Small concrete core

Pi — "core harness only"

10packages
2internal events

A small fixed core — kitchen, plumbing, load-bearing walls — poured in concrete and never moved. Everything else is furniture you carry in: one file, drop it in the right folder, it works.

Their internal message system is 102 lines and carries exactly two messages. Its own comment says, roughly: don't use me to remember things — go read the notebook.

Squadrant is six packages maintained by one person. It should live in Pi's house — a small core that doesn't move, and plugins that are just files.

But borrow this one thing from the big house DeepSeek's house has smoke detectors in every room. Not tests that run before you move in — alarms that are wired in and live while you're cooking. One of them is literally: "a dish was started and never finished — beep." That's the alarm that would have caught our stuck ticket on day one instead of month four.
The thing people get wrong "Everything is a plugin" sounds like the more advanced choice, so it sounds like the one to copy. It isn't — it's the right answer to a problem squadrant doesn't have (hundreds of packages, an outside ecosystem shipping add-ons). Copying the big house's floor plan would cost a lot and fix nothing. Copying its smoke detectors is cheap and fixes the actual bug.
03

So what do we build?

One rule: write down what you saw. Decide later what it meant.

Right now each waiter is asked to interpret on the spot — "is this important? yes/no" — and "no" means the message is gone forever. Instead, every waiter writes what they heard into one shared notebook, in one shared vocabulary. If a waiter hears something they don't recognise, they don't bin it — they write "heard something: <the exact words>" and that line gets counted. Only afterwards does one single person read the notebook and decide what it all means.

How it works now

  1. Five different watchers, each with their own shorthand.
  2. Each one decides on the spot whether what it saw matters.
  3. Anything it doesn't recognise is dropped, with no trace.
  4. What survives is folded into a status and the message itself is thrown away.
  5. So when something goes wrong, there is nothing to go back and read.

How it would work

  1. Same five watchers — but each only translates, never judges.
  2. Everything goes into one notebook, one vocabulary, in order.
  3. Unrecognised things are written down as "unknown" and counted.
  4. Alarms watch the notebook: started-but-never-finished beeps.
  5. The notebook is kept — so you can replay a bad day and see exactly what happened.
Why the notebook is the real prize Once a real bad day is written down, that file becomes a permanent test. You feed the actual recording of the stuck crew back through the new code and check it does the right thing — not a made-up example someone invented, the real thing that actually happened. Do that for #542, #704 and #492 and those three bugs can never quietly come back.
And one thing that's nearly free Separately from all of the above: a small script — maybe 150 lines — that reads the codebase and prints a table of "who sends this kind of message" and "who listens for it." Any row with an empty listener column is a bug you can see at a glance. DeepSeek generates exactly this table. It would have made #542 visible without changing a single line of running code.
If you remember one thing

Squadrant doesn't need a plugin framework. It needs a notebook.

A written-down, replayable, alarm-checked record of what its agents actually did — owned by one small module — plus a build-time table proving every kind of message has both someone sending it and someone listening. The framework question was never the real question.
